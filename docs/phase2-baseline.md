## Technical

- **Framework / build:** Astro `^5.0.0`, `output: 'static'`, `@astrojs/sitemap` integration. `prebuild` runs `node scripts/generate-llms.mjs` (regenerates `public/llms.txt` from content/data).
- **Site config:** `astro.config.mjs` sets `site: 'https://incenseherbs.com'`. The file still carries a `// TODO: replace with the production domain before launch.` comment (stale).
- **Hosting:** Not stated in-repo. `public/_headers` (Cloudflare `Content-Signal`, `X-Robots-Tag`, `Link: </llms.txt>; rel="describedby"`) and `public/_redirects` are Cloudflare-Pages conventions; deployment platform is unconfirmed from the repository alone.
- **URL structure:** trailing-slash routes — `/ingredients/{slug}/`, `/blog/{slug}/`, `/chinese-incense/`, `/wholesale/`, `/oem/`, `/contact/`, `/request-a-quote/`, `/safety/`. Slugs are stable kebab-case English names.
- **Canonical strategy:** per-page `<link rel="canonical">` computed in `BaseLayout.astro` from `Astro.url.pathname` against `Astro.site`. No per-page canonical override; single canonical per page.
- **Sitemap:** generated by `@astrojs/sitemap` → `sitemap-index.xml`; referenced from `robots.txt`.
- **Robots:** `User-agent: * / Allow: /` + `Sitemap:` line (also carries a stale `# Replace with the production domain` comment).
- **Redirects (`_redirects`):** 4 rules, all 301 → data site (`/data/*.json` and `/data` → `data.incenseherbs.com`). No redirect chains; no http→https or www rules present.
- **Status codes / 404:** fully static output; no custom `src/pages/404.astro` present (falls back to host default).
- **Indexability:** no `noindex` in `robots.txt` or `_headers` (`X-Robots-Tag: index, follow`). No `meta robots` found in templates.
- **Rendering / JS dependency:** static HTML; no client-side framework or heavy runtime JS. Fonts load from Google Fonts (Inter / Source Serif 4 / Noto Serif SC).
- **Performance:** not measured in this batch (no field/CrUX data). Assets are WebP-dominant (see images).
- **Image handling:** `public/images/` = 189 files (186 `.webp`, 2 `.png`, 1 `.jpg`). Inline `<img>` uses explicit `width`/`height` + `loading="lazy"`; alt text is descriptive. One shared `og-image-incense-still-life-1200x630.jpg`.
- **Pagination:** none (listing pages render full indexes; no paginated archives).
- **Breadcrumbs:** visual breadcrumbs on ingredient/blog/concept pages, mirrored in `BreadcrumbList` schema (Home → Ingredients/Guides → title).

## SEO

- **Title structure:** frontmatter `title` + template suffix — ingredients `«title» — LanDeng Ingredients`, blog `«title» — LanDeng`, concept `«title» — LanDeng`. 250 unique titles, **0 duplicates** (verified programmatically).
- **Title length:** a prior title-shortening batch (`docs/title-audit-2026-09.md`) already reduced over-length titles to ≤60 chars rendered.
- **Meta descriptions:** ingredients use the auto-derived `directAnswer` (Chinese + pinyin + type + botanical source + aroma); blog uses a per-post `metaDescription`; indexes/static pages have hand-written descriptions. No programmatic duplicate-description audit has been run (gap, see content-gap).
- **H1/H2 structure:** rich H2 decomposition — e.g. `agarwood.md` has 25 H2 sections (Key facts → Aroma → Botanical identity → Grades → Adulteration → Evidence & Sources). Consistent answer-first + evidence-tail pattern.
- **Duplicate titles/descriptions:** titles 0 duplicates; descriptions not yet dedup-audited.
- **Orphan pages:** 37 URLs with **zero inbound links** (36 ingredients + 1 blog: `incense-export-considerations`). Full map in `internal-link-map.md`.
- **Weak/thin pages:** no automated thin-page flag; all 150 ingredients carry full structured fields (Chinese/pinyin/scientific/aroma/sources).
- **Cannibalization:** 99 blog posts + 1 concept vs 150 ingredient pages share the agarwood/sandalwood "scent guide" territory; agarwood has 3 blog posts (`agarwood-grading-guide`, `agarwood-incense`, `agarwood-powder-vs-chips`) + 1 entity page — flagged for intent review in `content-gap-analysis.md`.
- **Internal linking:** 252 URLs mapped in `scripts/orphan_inbound.json`; 176 URLs have ≥2 inbound links. Entity↔article↔commercial wiring exists but is uneven (see `internal-link-map.md`).
- **Anchor text:** contextual entity-name anchors; no "Related Posts" keyword-stuffing pattern observed.
- **Taxonomy:** blog uses `pillar` (P1–P12 + Commercial + Editorial) + `cluster_role` (hub/article/guide/recipe/glossary/authority_reference/data_asset/buyer_intelligence/reference/history/how_to). Ingredients use a flat `type: ingredient` + `aroma[]` + `related[]`.

## Entity

- **Number of entities:** 150 ingredient entities (one Markdown file each) + 1 concept (`chinese-incense`).
- **Entity types:** all 150 `type: ingredient` (flat taxonomy; no separate material/form/technique entity types in the content collection).
- **Entity naming:** English slug + `title` (English + 中文), `chinese` (汉字), `pinyin` (tone-marked), `scientificName` (binomial).
- **Chinese names:** 150/150 present. **Pinyin:** 150/150. **Scientific names:** 150/150. **Aroma:** 150/150. **related[]:** 150/150.
- **Entity relationships:** `related[]` in frontmatter + `relationships.json` in the data site (150 records, 450 typed edges: category / aroma / …). Relationship types are category/aroma in the dataset; richer typed relationships (USED_IN / COMPARABLE_TO / HAS_FORM …) are **not yet** modeled.
- **Missing relationships:** no explicit `HAS_FORM`/`HAS_TECHNIQUE`/`COMPARABLE_TO` edges; `related[]` is a flat slug list without edge type.
- **Entity depth:** Tier-1 pages are deep (agarwood = 25 sections incl. botanical identity, grades, adulteration, commercial, evidence); long-tail pages are thinner but still carry the full frontmatter + sources. Tier breakdown in `entity-inventory.md`.

### Key inconsistencies discovered (carried into gap analysis)

1. `relationships.json` (450 edges) exists in the data site but is **absent** from the main-site `data/` and `public/data/` mirror (7 vs 8 files).
2. All 150 ingredient files carry `status: draft`, yet are built and served — the status field appears vestigial/unwired.
3. Homepage emits Organization + WebSite JSON-LD **twice** (`index.astro` and `BaseLayout` both emit it).
4. `llms.txt` lists only 2 of 8 datasets in its machine-readable section.
5. `_headers` / `robots.txt` / `astro.config.mjs` still contain stale "replace with production domain before launch" TODOs.
6. No custom 404 page.
